# CIC-004-001 — Knowledge Graph Constitution

## 1. Role

The Knowledge Graph (KG) is the **read-optimized, cross-domain, graph-native projection** of UCOS.
It is never a system of record (PRIN-001, PRIN-003): every vertex and edge is derived from events of
the owning domains, and the KG is rebuildable from the event log at any time (CR-003-001-04).

Uses: multi-hop traversal (compatibility, dependency, substitution), impact analysis (what breaks if X
changes), lineage and provenance navigation, recommendation features, AI grounding (DOM-AGT, CORPUS-017),
and governance queries.

## 2. Graph schema

### 2.1 Vertices

| Label set | Source events | Properties |
|-----------|---------------|------------|
| `:CommercialObject:<Type>:<Supertype>…` | `ucos.commercial-object.object.*` | `urn, tenant, typeRef, state, stateCategory, naturalKey`, attributes flagged `graphIndexed` |
| `:Party:<PartyKind>` | `ucos.party.*` | `urn, tenant, kind, status` (no personal attributes, §5) |
| `:TypeDefinition`, `:Facet`, `:Attribute` | `ucos.ontology.*` | `urn, namespace, name, version, state` |
| `:Policy`, `:Rule` | `ucos.policy.*`, `ucos.rules.*` | `urn, layer, kind, state` |
| `:Term` (taxonomy) | `ucos.ontology.term.*` | `urn, taxonomy, code` |
| `:Evidence`, `:Decision` | `ucos.evidence.*`, `ucos.decision.*` | `urn, kind, digest` |
| `:Any` aggregate of a plugin context | plugin-declared projection mapping | declared properties |

Every vertex carries `tenant`, `homeRegion`, `sourceSequence` (last applied `ucossequence`), `projectedAt`.

### 2.2 Edges

- One edge per DOM-REL `Relationship`, label = relationship type name (UPPER_SNAKE),
  properties `relId, validFrom, validTo, scopeDigest, ordinal` + edge attributes.
- Derived structural edges (not stored in DOM-REL, generated by projector): `INSTANCE_OF`
  (object → TypeDefinition), `SUBTYPE_OF`, `HAS_FACET`, `CLASSIFIED_AS` (object → Term),
  `GOVERNED_BY` (object → Policy where scope references it), `EVIDENCED_BY`, `DERIVED_FROM` (lineage).

## 3. Projection pipeline

```
events (all contexts) ─▶ kg-projector (consumer group per region, partitioned by tenant:aggregate)
   ├─ map event → upsert/delete operations via ProjectionMapping (metadata, per event type)
   ├─ apply idempotently: skip if event.ucossequence ≤ vertex.sourceSequence
   ├─ batch writes (≤ 1,000 ops / 50 ms) through GraphStorePort (openCypher MERGE semantics)
   └─ checkpoint offsets after durable write
```

ProjectionMappings are metadata (`urn:ucos:<ns>:kgmap:<eventType>`), allowing packs and plugins to
project new aggregates without changing the projector (PRIN-013).

Rebuild: a **blue/green** rebuild projects from offset 0 (or archive) into a new graph generation,
validates counts and digests against the live generation, then switches the read alias atomically.

## 4. Query surface

- `POST /v1/knowledge-graph:query` — **parameterized, named queries only** (registered metadata
  `urn:ucos:<ns>:kgquery:<name>` with openCypher/GQL text, parameter schema, max depth, max rows).
  Ad-hoc query text from clients is forbidden in production (injection and cost control); allowed in
  sandbox environments for users with `kg.query.adhoc`.
- `POST /v1/knowledge-graph:traverse` — TraversalSpec (DOM-REL) executed on the projection for depth > 3.
- `POST /v1/knowledge-graph:impact` — impact analysis: given a changed vertex, return dependents
  reachable via edges whose type has `semantics ∈ {composition, dependency, requires}` up to depth 8,
  grouped by owning context.
- Limits (policy `kg.query-limits`): default max depth 8, max rows 10,000, timeout 2 s, cost budget
  per tenant per minute.

## 5. Security in the graph

1. Tenant isolation: every query is rewritten by the KG gateway to bind `$tenant` on every vertex
   pattern; queries not passing the rewrite validator are rejected.
2. Row-level authorization: results are post-filtered through PDP `kg.vertex.read` per vertex label;
   denied vertices are removed together with edges incident to them; paths through denied vertices are
   removed (no inference across hidden nodes).
3. No personal data: only identifiers and non-personal attributes are projected. Personal attributes
   are fetched from the owning domain with authorization when needed.
4. Temporal correctness: queries accept `asOf`; edges filtered by `validFrom ≤ asOf < validTo`.

## 6. Inference

Rule-based inference is limited to **materialized derived edges** defined as named KG rules
(e.g. `COMPATIBLE_WITH` transitive over `REPLACES`) — computed by the projector, versioned, labeled
`inferred: true` with `ruleRef`. Inferred edges never flow back into DOM-REL; promoting an inference to
a fact requires a DOM-REL command with Evidence referencing the inference rule (DOM-KNW governs).

## 7. Certification Rules

- **CR-004-001-01** Rebuilt graph equals live graph (vertex/edge counts per label, property digest) after replay of ≥ 10⁸ events.
- **CR-004-001-02** Tenant-isolation fuzzing: 10⁵ generated named-query invocations with forged parameters never return another tenant's vertex.
- **CR-004-001-03** Projection lag p99 ≤ 2 s at 20,000 events/s per region.
- **CR-004-001-04** Hidden-vertex test: a vertex denied by PDP never appears in results, nor do paths through it.

## 8. Validation Rules

- **VR-004-001-01** Every event type consumed by the projector has a ProjectionMapping; every mapping targets labels defined in §2 or a certified pack.
- **VR-004-001-02** Every registered named query declares max depth and max rows within policy limits.
